# בדיקת מוכנות לפתיחת שירות אימות החברות — 8 בספטמבר 2026

## החלטה

**אין אישור לפתיחת חיוב. ההשעיה נשארת פעילה.**

השירות הראשון המוצע לפתיחה עתידית הוא אימות חברה בלבד: `POST /v1/verify/mainnet`, במחיר ייחוס 0.05 USDC על Base. זהו יעד לבדיקה, לא שירות זמין לרכישה או אישור מסחרי. שאר השירותים אינם מאושרים לפתיחה בעקבות הדוח הזה.

הבדיקה מבוססת על גרסת Production `7eb2d9172a162669f9d07d72be0593fa6ae7a8dd` ועל ענף התיקון `fix/payment-readiness-20260908`. אין פריסת Production או פתיחת תשלומים כחלק מהשינויים בענף. פריסת Preview אוטומטית עשויה להיווצר בעקבות חיבור GitHub, בהתאם להגדרות האירוח הקיימות. אין חתימות ארנק, עסקאות, שינויי סודות, פניות חיצוניות או הרשאות פיילוט חדשות.

## תוצאות ביצוע

- בסיס לפני השינויים: `npm run check` עבר עם 183 בדיקות Vitest ועוד 11 בדיקות Node, כולל build.
- אחרי תיקוני התשלום: `npm run check` עבר עם 199 בדיקות Vitest ועוד 11 בדיקות Node — 210 בסך הכול, תוספת של 16. גם format, lint, typecheck ו־build עברו.
- smoke של ה־build המתוקן ב־loopback: **42 בקשות עברו**, עם אפס ניסיונות תשלום אמיתי; כל כלי התשלום נשארו מושעים והגישה לפיילוט ללא הרשאה נדחתה.
- נוספה `npm run smoke:suspended:local`, שמפעילה שרת ולקוח באותה הרצה ומכבה את השרת בסיום. חיבור לשרת משתי פקודות נפרדות נכשל ב־loopback בסביבת העבודה הזו; ההרצה המאוחדת עברה.
- נוספה ראיה לנתיב שנכשל בזמן שגיאת רשת ב־smoke. בדיקה מול פורט loopback סגור החזירה `FAIL` וקוד יציאה 1 עם `/health`; היא לא מסומנת כהצלחה.
- ב־Production כל שבעת מסלולי REST החזירו השעיה גם ללא חתימה וגם עם סמן סינתטי לא תקין. Health וקובצי הגילוי שנבדקו היו זמינים. הבדיקה המלאה נעצרה ב־timeout של 20 שניות במהלך MCP, ולכן **אין סימון PASS מלא ל־Production בהרצה הזו**.
- בדיקה ממוקדת חוזרת של `tools/list` ו־`verify_company` בשני שרתי MCP עברה: 13 כלים והודעת השעיה. זמני התגובה ממבצע הבדיקה היו כ־15 שניות; לא אומתה סיבת ההאטה ואין להסיק שזהו זמן העיבוד של השרת.
- בשאילתות Vercel לא נמצאו שגיאות Runtime או אירוע `external_paid_call` בטווח 24 השעות שנבדק. זה אינו אישור הכנסות לכל חיי השירות או בדיקת יתרת ארנק.

## חסמים שמחייבים עבודה או החלטה נפרדת

### 1. אירוח שמתיר שימוש מסחרי — חסם מאומת

המחבר המורשה של Vercel החזיר שהחשבון המאחסן נמצא בתוכנית `hobby`. לפי [תנאי השימוש ההוגן של Vercel](https://vercel.com/docs/limits/fair-use-guidelines), תוכנית זו מוגבלת לשימוש אישי ולא מסחרי; ההגדרה כוללת גם פרסום שירות למכירה ולא רק גביית כסף. עצירת תשלומים אינה כשלעצמה הוכחה שכל האתר עומד בתנאים.

לא שודרגה תוכנית ולא הועבר הפרויקט. נדרשת בחירת אירוח/אישור שמתירים את השימוש המתוכנן. אם נשמרת מגבלת אפס הוצאה, יש לבדוק חלופה חינמית שמתירה שימוש מסחרי ותואמת ל־Node, למסד הנתונים ולמגבלות האבטחה, לפני הצעת מעבר לאישור. אין כאן קביעה שקיימת כבר חלופה מאומתת ומתאימה בחינם.

### 2. הזמנות, תשלומים ומסירת דוחות — חסם טכני

לוגים או מונה בזיכרון אינם תחליף לרישום מתמשך. גם מניעת שימוש חוזר ב־nonce בבלוקצ'יין אינה מוכיחה שהקונה יקבל את הדוח לאחר timeout. אין לבנות ledger מקומי בזיכרון/דיסק זמני ולסמן את החסם כסגור.

לאחר בחירת אחסון מתמשך מורשה, נדרש לממש במסלול האימות המצומצם:

1. מזהה הזמנה וקישור חד־משמעי לזהות קונה מאומתת, בקשה מנורמלת, שירות, מחיר, רשת, נכס ומקבל. מזהה הזמנה לבדו אינו הרשאת הורדה.
2. שמירת תוצאת הדוח כפרטית **לפני** שליחת settlement, לאחר אימות התשלום; שמירת זהות גרסת הדוח ומצב ניסיון התשלום. כשל בשמירה מונע שליחת תשלום.
3. רישום מצב `SETTLEMENT_PENDING` באופן אטומי לפני פנייה ל־facilitator. נעילה/ייחודיות מונעות שתי פניות עבור אותו ניסיון תשלום, גם בין תהליכים.
4. מעבר ל־`SETTLED` רק עם ראיות תואמות; שמירת מזהה עסקה ורשת עם מפתח ייחודי מתאים. שמירת כשל מפורש בנפרד מ־`SETTLEMENT_UNKNOWN`.
5. timeout או קריסה אינם אישור לחייב שוב. משימת התאמה צריכה לבדוק את התוצאה הקיימת ולהעביר למצב מתאים; לקוח לא מתבקש לחתום מחדש אוטומטית.
6. ניסיון הורדה חוזר מאומת מחזיר את אותו דוח שנשמר, ללא חיוב נוסף. ניסיון להשתמש באישור ישן עבור חברה אחרת, שירות אחר או קונה אחר נדחה.
7. טיפול מתועד במקרה של חיוב ללא יכולת מסירה, כולל החלטת החזר ומסמך חשבונאי מתאים. שום בדיקה אוטומטית אינה רשאית לבצע החזר אמיתי בלי הרשאה.

דוחות ונתוני התאמה צריכים להיות מוגנים בהרשאות ובמדיניות שמירה. אין לרשום מפתחות, חתימות תשלום או תוכן חשבוניות בלוגים ציבוריים; כל שמירה נדרשת של חומר רגיש מחייבת תכנון גישה והצפנה מתאים.

מבחני קבלה נדרשים: שתי בקשות מקבילות, הפעלה מחדש בין כל שני שלבים, אותו מפתח עם קלט שונה, כשל DB לפני ואחרי settlement, כשל מקור מידע, קבלה חלקית, תשלום כפול עם מזהה בקשה אחר, שחזור דוח לאחר timeout, גישה של קונה אחר והחזר. יש לאמת זאת מול האחסון האמיתי שנבחר — לא רק מול mock.

### 3. הגדרות מסחריות, נתונים ופרטיות — טעון בירור, לא אישור משפטי

אין בקוד ראיות מספקות לזהות מפעיל מסחרי מאושרת, הסדרת מסמכי עסקה ותקבולים ב־USDC, תנאי שירות/החזר, מדיניות פרטיות ושמירה, או מיפוי רישיונות לכל מקור נתונים. נדרשת בדיקת הדרישות החלות בפועל לפי מודל השירות ונתוניו; אין להסיק אוטומטית שנדרש רישיון KYB רק מהשם, או שהיות המידע ציבורי מתירה כל שימוש.

המידע הממשלתי על [פתיחת תיק עוסק פטור באינטרנט](https://www.gov.il/he/service/request-open-exempt-dealer-via-internet) מציין שהשירות ללא עלות. זו אינה קביעה בדבר זכאות המפעיל או הסיווג המתאים, ואינה אישור להתחיל לגבות לפני הבירור. לא הוגשו טפסים ולא נעשתה פעולה בשם המפעיל מול רשות.

מקור נתוני האימות בקוד הוא משאב `f004176c-b85f-4542-8901-7b3176f9a054` ב־data.gov.il. אישור רישיון ספציפי למשאב ולשימוש אינו מתועד בדוח זה. נדרשת בדיקה גם אם כבר קיימת גישה טכנית ל־API.

### 4. אבטחה ותפעול מתמשכים

יש להשלים אכיפת קצב ותקציב בין מופעים, בדיקות TLS/timeout של קריאות manifest/JWKS, ושמירת/התראת אירועי תשלום לא ודאי. הלוגים הזמינים ב־Vercel אינם ארכיון חשבונאי. אין להסיק מהיעדר אירוע בטווח 24 שעות שלא היה אירוע כלשהו מאז הקמת השירות.

## פיילוט ללא חיוב — תסריט מוכן, לא הזמנה שנשלחה

עד לבחירת אירוח מותר אין לפתוח קמפיין מסחרי או גישה חדשה. לאחר אישור מתאים:

- לבחור שותף בעל צורך ממשי באימות ספק ישראלי ולהגדיר מדד קבלה: שילוב בפועל בתהליך שלו ותועלת מוגדרת, לא רק `initialize` או `tools/list`.
- להפעיל פיילוט קצר ומוגבל דרך `/v1/pilot/verify` או `/mcp/pilot` רק עם הרשאה נפרדת. אין להוריד אימות בנתיב בתשלום ואין לפרסם token.
- לתעד שימוש אמיתי, מה חסר והאם השותף מוכן לרכוש במחיר הייחוס לאחר פתיחה. מוכנות מילולית וריצה חינמית אינן הכנסה.
- לאחר סגירת חסמי הפתיחה ואישור כתוב, לבצע בדיקת רכישה עצמאית של הקונה בכספו, אישור מסירה ורישום. ללא מימון מוכר, תשלום עצמי או הבטחת עסקה מהשותף.

## הרצה חוזרת בטוחה

```sh
npm ci --ignore-scripts
npm run check
npm run smoke:suspended:local
```

לבדיקת השירות הקיים, כאשר ההשעיה נשארת פעילה:

```sh
npm run smoke:suspended -- https://israel-counterparty-intelligence.vercel.app
```

ה־smoke משתמש בנתונים סינתטיים ובסמנים שאינם חתימות. הוא בודק השעיה ושירותים חינמיים, ואינו בודק settlement אמיתי. אין להריץ `smoke:paid`, `smoke:mcp:paid` או כלי buyer עם `--pay` כחלק מתהליך זה.

## מה נשאר ללא שינוי

- `PAID_SERVICE_SUSPENDED = true`.
- הגדרות Production, הארנק, המפתחות, המחירים והרשאות הפיילוט.
- אין מיזוג ל־main, אין שדרוג אירוח ואין פתיחת גישה מסחרית במסגרת ענף זה.
- הצלחת הבדיקות היא אישור לתיקונים שנבדקו בלבד; אין כאן אישור שהעסק מוכן להכנסה.
